# Проектное видение — Real-Time Trilingual Translator (RU/EN/DE)

**Автор:** Codex (GPT-5)  
**Дата:** 2025-10-19  
**Подход:** OpenAI-First, минимализм инфраструктуры, максимальная делегация SDK

---

## 1. Стратегическое понимание
- **Миссия** — предлагать мгновенный перевод между русским, английским и немецким языками с минимальными задержками, высокой надёжностью и прозрачной архитектурой.
- **Принцип** — вся интеллектуальная логика делегируется официальному OpenAI SDK. Мы избегаем промежуточных фреймворков, собственных агентов и тяжёлых оркестровок.
- **Ценность** — быстрый путь от идеи до продакшена: тонкий backend для авторизации, квот и метрик; лёгкий frontend со Streaming UI; единый вектор развития — Responses и Realtime API.

---

## 2. Целевое состояние системы

### 2.1 Backend (FastAPI + OpenAI SDK)
- **Роль** — «шлюз доверия»: аутентификация (JWT), rate limiting, аудит и метрики. Никакой «бизнес-логики перевода» не реализуется локально.
- **Интеграция с OpenAI** — использовать `AsyncOpenAI` (Responses API) для текста и Realtime Sessions для голоса. Любые блокирующие операции завернуть в `asyncio.to_thread` или полностью перейти на асинхронного клиента.
- **Наблюдаемость** — Prometheus метрики (`translations_total`, `translation_latency_seconds`), структурированное логирование, опционально — OpenTelemetry.
- **Кэш** — время жизни ответа зависит от конфигурации, значения TTL уважаются. Для горизонтального масштабирования подключается Redis.
- **Безопасность** — переход на RS256, минимизация секретов в конфиге, режим «least privilege» для Realtime-токенов, лимит размера запросов, антиспам-защита.

### 2.2 Frontend (Next.js 14)
- **UI-философия** — «минимум кликов, максимум обратной связи». Стартовый экран = поле ввода, выбор языка, статус потокового перевода.
- **Streaming UX** — клиентский SSE-ридер с буферизацией частичных строк, отображение прогресса и тайм-метрик (first-token latency, total latency).
- **Режимы работы**:
  1. **Text-to-Text** — основной сценарий через Responses API.
  2. **Voice-to-Voice (позже)** — WebRTC с ephemeral token, отображение субтитров.
- **Инфраструктура** — Next.js standalone build, совместимость с Vercel/Netlify, возможность Edge-рендеринга для быстрых ответов.

### 2.3 Операционная модель
- **CI/CD** — GitHub Actions или аналог (тесты, линтеры, проверки типов). Docker-образы публикаются в регистри. Terraform/IaC – опционально, но если упоминаем, то хранится в репозитории.
- **Dev Experience** — Makefile/Poetry scripts, единые lint-команды (`ruff`, `mypy`, `npm run lint`), локальный запуск через Docker Compose.
- **Мониторинг & Алёрты** — правила для HTTP 5xx, превышения времени ответа, лимитов OpenAI API.

## 5. Лучшие практики OpenAI-First
- **Единый SDK** — никаких сторонних обёрток поверх OpenAI; прямое использование `responses` и `realtime`.
- **Минимизация состояния** — только то, что необходимо для auth и кэша. Данные пользователей не храним дольше TTL.
- **Прозрачность** — документация соответствует коду (если сервис недоступен — помечаем как TODO).
- **Fail loud** — различаем ошибки OpenAI (429, 5xx) и системные, ретрай/бэкоф при квотах.
- **Тесты** — контрактные тесты на API, unit-тесты для парсинга SSE, smoke для Realtime.
- **Невоенный лексикон** — соблюдение политики OpenAI по безопасному использованию модели.

## 6. Пользовательский сценарий (пример)
1. Пользователь открывает фронтенд и запрашивает JWT — backend создаёт токен, логирует событие, обновляет метрики.
2. Пользователь вводит текст → запрос `/translate/stream` с JWT.
3. FastAPI проверяет лимиты, обращается к Responses API и стримит кусочки результата.
4. Фронтенд буферизует частичные `data:`-события, показывает перевод и время до первого токена.
5. Метрики фиксируют успех, кэш сохраняет ответ с TTL.

## 7. Принципы расширения
- Новые языки → добавляем в конфиг `Language`, в промпт — автоматически.
- Новые форматы ввода (PDF, аудио) → обрабатываем на клиенте или в тонких службах до отправки в OpenAI.
- Интеграции (Slack, Teams) → строим поверх существующего API, не меняя сердцевину.

## 8. Итоговое видение
Real-Time Trilingual Translator остаётся эталонным примером OpenAI-First продукта: минимальный собственный код, максимальная опора на платформу. Главные цели — устранить асинхронные узкие места, синхронизировать документацию с реализацией и довести голосовой режим до production-ready состояния. При соблюдении этой стратегии команда сможет масштабировать продукт на другие языки/форматы, не жертвуя простотой и скоростью развития.
